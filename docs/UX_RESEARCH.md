# 向野：旅行规划体验调研与迭代记录

更新：2026-09-27

## 用户要完成的事

1. **从一句话到可执行的四天行程。** 用户给出出发地、目的地、天数和必去地点，希望每天有具体安排，并能在保存前修改。
2. **边看安排边校对地图。** 每天的地点、时间、费用和道路位置要能互相对照；手机上先看到行程，再展开地图。
3. **出发前发现缺口。** 用户需要知道预算、待办、交通与住宿、日程冲突，而不是只看一份漂亮的路线。
4. **带走计划。** 行程要能导出到个人日历；车票、酒店、开放时间和价格必须提示核验。
5. **发现适合自己的目的地。** 已有计划应成为首页的继续入口，目的地照片需要与地点真实对应。

这些任务来自向野当前页面与用户反馈，不代表已做用户访谈。下一轮应观察真实用户完成上述任务的时间、误点和放弃点，再调整优先级。

## 本轮设计原则

- **先给结论，再给地图。** 手机首屏展示计划概览和每天安排，地图用于核对位置与路线。
- **可操作的信息比装饰优先。** 预算、未完成清单、时间重叠都能直达对应页面或日期。
- **保持来源可追溯。** 目的地使用对应地点的授权照片，来源记录在 `assets/IMAGE_CREDITS.md`。
- **演示能力不冒充实时服务。** GitHub Pages 版的自然语言规划使用精选地点库；机酒玩乐仍为模拟，实时路况、班次、房态和下单未接入。
- **尊重已有计划。** 发现首页为已有行程提供继续编辑入口，不要求用户从零开始。

## 后续验证与优先级

1. **高：真实规划测试。** 用“北京到乌兰布统四天，必须去将军泡子和公主湖”等任务，检查每日地点数量、车程、时间重叠、预算与必去地点覆盖。仅有坐标并不代表路程合理。
2. **高：云端同步与账户。** 当前数据只在浏览器本地；跨设备和协作仍需要账户、存储与权限设计。
3. **中：交通、住宿和玩乐的真实供给。** 接入合规服务后才展示实时价格、库存、订单与售后；现阶段持续标记模拟。
4. **中：地图和地点可靠性。** 为路线服务增加稳定配额与失败提示；针对新增地点保存来源、坐标和更新时间。
5. **中：可用性与无障碍。** 邀请至少 5 名目标用户分别在手机和桌面完成新建、调整、加地点、导出任务；记录完成率和困惑处，复查键盘导航与文字对比度。

## 2026-09-27 视觉更新

用户希望界面更青春，并减少绿色占比。本轮采用蓝紫作为主要操作色，珊瑚橘标记创建、添加等动作，浅紫、浅蓝和暖白用于区分信息层级；目的地照片保留实景颜色。导航、按钮、卡片、计划封面、市场、个人页和小野助手都使用同一组颜色。首页大图改用大理洱海照片与蓝紫遮罩，避免整个首屏被绿色林地图像主导。

配色与可读性参考 [Material Design 的色彩与对比度指导](https://m1.material.io/style/color.html)：明亮色用于短标签和重要动作，大面积背景保持低饱和度；小字号白字按钮使用更深的珊瑚红。最终仍需邀请真实用户测试文字、地图与照片上的对比度。

## 2026-09-27 旅途闭环更新

再次对照 [Wanderlog 的逐日行程、地图与清单](https://wanderlog.com/home)、[Roadtrippers 的逐站编辑流程](https://support.roadtrippers.com/hc/en-us/articles/200632079-Planning-a-Trip-on-Our-Website) 和 [Airbnb 收藏清单的回访入口](https://www.airbnb.com/help/article/1236)，向野本轮处理了三个已能验证的断点：

- **计划到出发：** 出发页随日期显示预览、旅途中或回顾，按天查看各站；未来日期不能提前记录到达。行前清单来自当前行程，不再固定显示同一组提醒。
- **出发到足迹：** 带真实坐标的地点在记录到达后进入足迹；足迹跨所有本地行程汇总，显示实际点击时间。餐饮、住宿和长途交通的占位安排可以标记完成，但不会被当作到过的地点。
- **发现到收藏：** 个人页列出收藏目的地，能直接重新打开规划。社区的精选、最新和本地发布采用不同排序；喜欢只保存在当前浏览器。

机票酒店与当地玩乐仍是通用演示方案。页面在已有行程时使用目的地照片作封面；未创建行程时可以浏览详情，但需要先有行程才能生成模拟订单。没有接入真实库存、支付、跨设备同步或公开社区发布。

## 2026-09-27 日光地图与视觉细化

参考 [MapLibre 样式规范](https://maplibre.org/maplibre-style-spec/)对底图图层、标签和颜色的分离方式，以及 [Mapbox Standard 文档](https://docs.mapbox.com/map-styles/guides/standard-styles/)对地点标签可见性的控制，保留真实矢量街道底图，制作了优先显示中文地名的日光样式。公园、水域、道路、建筑分别使用低饱和的薄荷、水蓝、杏色和暖灰，行程标记使用更醒目的蓝紫、珊瑚、海蓝和莓紫。

全部旅程的地图标记显示“第几天 / 第几站”，避免不同日期都出现孤立的 1、2、3；地点名在总览时可悬停查看，选择单日后直接展示。地图旁的日程概览也加入选日提示，减少用户面对大片空白时的困惑。地图路线仍只在道路服务成功返回后绘制，公开网页不以直线冒充实际道路。

其他页面将暖白和实景照片作为主体，把珊瑚橘用于主要行动、蓝紫用于选择状态，减少大面积紫色背景。调整了发现页标题与文案的排版、地图工具栏和移动端地图控件。下一步应请用户在手机上完成“切换日期、找到地点、查看详情、添加地点”任务，检验郊野地区较稀疏的公开地图数据是否足够辨认位置。

## 2026-09-27 地图样式再次调整

根据“地图款式不合适”的反馈，将上一版日光配色与多色方形标记撤下。当前默认地图采用更接近常见中文街道图的中性浅底、暖黄道路、淡绿公园和淡蓝水域；行程地点统一使用蓝色圆形编号标记，道路路线成功返回时也用蓝色突出。地图控件改为朴素的白底按钮，减少装饰与地图信息竞争。另一种简洁样式仍可手动切换。

这一调整参考了 [百度地图 JSAPI 的地图样式说明](https://lbs.baidu.com/docs/jsapi?title=jsapi4%2Fguide%2Fmap%2Fstyle)和 [圆周旅迹的官方 App Store 页面](https://apps.apple.com/cn/app/id6473148424)所展示的地图与日程组合；底图数据和绘制服务仍然是 OpenFreeMap / OpenStreetMap，不能声称已切换到百度地图底图。郊野地区的地名和道路密度受公开地图数据限制。
