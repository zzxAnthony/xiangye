# 向野 Web

响应式旅行规划网页项目。参考 `reference/` 中的产品资料，扩展了计划工作台、真实地点与道路路线、个性化推荐、机票酒店与当地玩乐页面和本地小模型助手。无需前端构建工具，Python 3 即可运行。

## 启动

```bash
python3 server.py
```

打开 <http://localhost:8000>。使用其他端口：`PORT=8080 python3 server.py`。

## GitHub Pages 在线版

公开访问地址：[向野在线版](https://zzxanthony.github.io/xiangye/)。GitHub Pages 只托管静态文件，网页会自动切换到基础演示模式：精选地点搜索、基于地点库的中文行程草稿、确认保存、预算和清单问答可在浏览器使用。页面明确标出这不是云端模型；百度地点搜索、道路路线和本地 Qwen3 自由问答需要运行上面的 Python 服务，在线版没有连接这些接口。机酒玩乐仍是模拟商品与订单。

计划、偏好和动态保存在访问者自己的浏览器，换设备不会自动同步。密钥只存在本机 `.env.local`，不提交到 GitHub。

## 已实现

- 发现页、目的地搜索和灵感卡；已有行程会在首页提供继续编辑入口。目的地卡片使用对应地点的授权照片。
- 新建行程、日期/人数/预算/节奏校验，使用有真实坐标的精选地点生成多日行程，并持久化在浏览器本地。
- 计划工作台：旅行封面、按天卡片、可缩放城市矢量地图、道路路线、地点搜索、添加、移动、顺序建议、替换预览、时间和备注编辑、锁定和记录到达；可从攻略文字提取精选地点，编辑出发日期与预算。手机端优先展示每天安排；预算、待办、交通住宿和时间重叠集中在出发前核对区，并可导出 `.ics` 日历文件。
- 发现与社区：目的地推荐结合兴趣、已有行程、收藏和浏览记录；故事可打开阅读。社区支持按精选、最新和本地发布筛选，并在当前浏览器中记录喜欢。
- 我的页面：兴趣、出发地、节奏、预算习惯、同行方式和步行偏好；可关闭并清除浏览记录。
- 每页可拖动的悬浮小野助手，手机上避开底部导航；当前使用免费的本地 Qwen3 1.7B（模型文件约 1.4 GB），通过 Ollama 非推理模式返回正文。后端也保留兼容 API 的托管模型配置。
- 独立“机票酒店 · 当地玩乐”页，手机底部导航可直接进入：可浏览车票机票、住宿、景点门票与当地玩乐的演示方案，筛选、收藏、查看详情、生成和取消模拟订单；还可查询真实地理地点并加入行程。
- 预算、记账、行前清单、出发模式、足迹和社区本地动态。出发页按实际日期区分预览、旅途中与回顾，逐日查看并记录完成；足迹汇总所有行程中已标记到达的真实坐标地点，记录点击时间；我的页面可重新打开收藏的目的地。

## 视觉设计

页面采用暖白、珊瑚橘、蓝紫和浅水蓝的配色。发现、计划、机酒玩乐、社区、个人页和悬浮助手共用导航、按钮与卡片样式；手机端保留逐日安排优先的阅读顺序。计划地图使用清晰的标准街道样式，优先显示中文地名；地点标记统一为蓝色编号，选中某一天后显示地点标签。设计取舍见 [体验调研记录](docs/UX_RESEARCH.md)。

## 地图与外部数据

默认标准街道地图基于 OpenFreeMap Bright 调整，可切换到简洁地图样式；使用 Leaflet、MapLibre GL 与适配插件渲染。地图样式来源及授权见 [地图说明](assets/map/README.md)，相关前端文件位于 `vendor/`。现有百度 AK 可用于服务端签名地点搜索，但在当前本地地址调用百度 JavaScript API 未通过浏览器端验证；使用百度交互底图需要可用的浏览器端 AK 及对应白名单。精选 POI 的 WGS84 坐标来自 OpenStreetMap Nominatim。主动地点搜索优先调用 `/api/map/search` 的百度地图 POI，服务端把 BD09 坐标转换为 WGS84 供地图与路网使用；百度不可用时回退 `/api/geo/search`。按天路线使用 `/api/geo/route` 调用 Valhalla / OpenStreetMap 公共演示服务。路网服务失败时明确显示错误，不画虚构线路。公共演示服务不保证可用性，正式部署需自有或商用服务额度。

百度地图 AK 与用户提供的 SK 已在本机 `.env.local` 配置并验证，地点检索可返回结果。密钥只放服务端，不会送到浏览器；部署到其他机器时需要重新配置。

## 模型配置

本机已安装并运行 Ollama，下载 `qwen3:1.7b`，`.env.local` 设置 `LLM_PROVIDER=ollama`。如需重建：安装 Ollama，执行 `ollama pull qwen3:1.7b` 和 `brew services start ollama`，再启动本项目。模型只基于当前行程摘要和偏好回答，不能直接修改行程或下单。

如需使用托管模型，删除 `LLM_PROVIDER=ollama`，设置 `LLM_API_KEY`、`LLM_MODEL`，以及需要时的 `LLM_BASE_URL` / `LLM_API_STYLE`。

## 数据与预订边界

行程、偏好、记账、浏览记录、收藏和模拟订单保存在当前浏览器，不跨设备同步。机票酒店与当地玩乐页的所有商品、价格和订单都标为模拟，不会付款或真实预订。真实商品须在铁路 12306、携程或美团核验，购买与售后由对应平台负责。计划中的餐饮、交通和住宿预留费用也明确标为模拟预算。
